# 手机练习意外返回首页

## 触发链

排查基线：线上提交 `26506a6`，用户使用 SideStore 安装的 iOS App。

`AppShell` 全局挂载 `PullToRefresh`。当 `.workspace` 滚动到顶部时，
一次单指向下滑动约 165 CSS px 会达到刷新阈值，松手后无条件执行
`window.location.reload()`。重新启动时，导航状态初始化为 `home`，
内存中的练习页面随之消失。

题卡内部已有 `data-no-pull-refresh`，但它只保护题卡后代；练习区域的
空白、卡片外边缘、独立解析面板仍受全局监听。因此同样的阅读滑动，
落点不同就会表现为偶发刷新。桌面通常没有触摸下拉，所以更难遇到。

iOS 只禁止注册 Service Worker，并没有禁止这套网页刷新手势。
原生包里的资源也无法通过网页刷新更新；即使没有 Service Worker，
旧代码仍在 `finally` 中重新加载 WKWebView。

## 修复边界

- 整个练习视图卸载下拉刷新组件，覆盖所有空白与解析区域。
- 原生环境通过平台适配层识别后，不注册下拉刷新监听、不显示刷新提示。
- 网页刷新等待 Service Worker 更新期间，如果进入练习、组件已卸载，
  更新完成后不得继续重载新的练习页面。
- 双指触摸或滚动离开顶部时取消当前刷新手势。
- 网页非练习页面继续支持原有下拉刷新。

本次不改动答题、练习记录、同步协议或数据库格式。Service Worker 自身、
普通前后台生命周期和错误边界没有静默返回首页的代码路径。
iOS 若因内存压力终止应用，冷启动仍默认首页；这与已确认的触摸刷新
触发链不同，不能仅凭本次代码审计声称已验证或解决系统进程终止。
